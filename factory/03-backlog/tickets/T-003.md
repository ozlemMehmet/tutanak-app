## Kapsam
Emlak ofisi yoneticisi/danismani rolundeki kullanicinin e-posta + sifre ile hesap olusturmasi ve giris yapmasi. Basarili giris sonrasi korumali endpoint'lere erisim icin bir oturum/erisim token'i verilir.

PRD baglami: "H-08 | Selin | Emlak ofisi yoneticisi olarak, e-posta+sifre ile hesap olusturup giris yapmak istiyorum, cunku ofisimin tutanak kayitlarina guvenli erisimim olsun." (Kapsam ici madde 8).

## Kabul Kriterleri (test edilebilir)
- [ ] Gecerli e-posta + sifre ile kayit istegi 201 doner ve kullanici veritabaninda olusturulur.
- [ ] Sifre veritabaninda duz metin olarak saklanmaz (hash'lenmis deger dogrulanabilir).
- [ ] Zaten kayitli bir e-posta ile tekrar kayit denemesi 409 + alan bazli hata mesaji ("bu e-posta zaten kayitli" benzeri) doner.
- [ ] Gecerli kimlik bilgileriyle giris istegi 200 + erisim token'i doner.
- [ ] Hatali sifre ile giris istegi 401 doner.
- [ ] Token olmadan korumali bir endpoint'e yapilan istek 401 doner.

## Tur 3 Ek Kriterleri (QA iadesi + anayasa karari)

Bu iki madde de T-003'un kendi getirdigi `bcrypt` bagimliliginin dogrudan sonucudur,
kapsam genislemesi degildir.

- [ ] **`bcrypt` pini `^6.0.0`.** `apps/api/package.json` + `package-lock.json` guncellenir.
      `bcrypt` `main`'de yoktur; urune bu ticket ile ilk kez girer, dolayisiyla surum secimi
      bu ticket'in kapsamidir (CLAUDE.md §6.1 notu). `hash`/`compare` API'si 5.x ile ayni,
      beklenen degisiklik pin + lockfile.
- [ ] **`npm audit --audit-level=high` cikis kodu 0.** 5.1.1'in
      `@mapbox/node-pre-gyp` → `tar` zinciri 2 high + 1 critical uretiyordu ve CI'daki §9
      kapisi bu yuzden kirmizi doner; 6.0 o zinciri terk ettigi icin sorun kokten kalkar.
- [ ] **Repo kokune `.dockerignore` eklenir** ve en azindan `**/node_modules`, `apps/*/dist`,
      `apps/*/coverage`, `.git` haric tutulur.
- [ ] **`docker compose up -d --build` sonrasi API gercekten ayaga kalkar** ve
      `curl http://localhost:3000/health` basarili yanit doner.
- [ ] Yukaridaki 6 kabul kriterinin **tamami** calisan API uzerinde gercek HTTP istekleriyle
      dogrulanir (onceki QA turunda hicbiri test EDILEMEDI).

QA'nin dogruladigi kok neden (`factory/05-dev/T-003-review-feedback.md`): `.dockerignore`
olmadigi icin `Dockerfile`'daki `COPY . .`, `npm ci`'nin container icinde kurdugu linux
native binding'i host'un macOS (Mach-O) `bcrypt_lib.node` dosyasiyla eziyor; Nest sureci
`ERR_DLOPEN_FAILED` ile cokuyor. `.gitignore` bunu engellemez, `docker build` context'ini
yalnizca `.dockerignore` etkiler. Kusur T-001'den beri vardi ama ilk native bagimlilik bu
ticket'la geldigi icin simdi tetiklendi.

Not: duzeltmeden sonra `docker compose down -v` ile eski named volume'lar temizlenmeli;
`api-node-modules` volume'u ilk olusturuldugunda bozuk binary'yi almis olabilir.
